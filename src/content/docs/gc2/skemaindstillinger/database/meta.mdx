:::note[Krævet adgang]
Du skal kunne ændre lagets egenskaber. Meta gælder i alle Vidi-konfigurationer, der viser laget.
:::

Meta er lagets indstillinger til Vidi. Her bestemmer du f.eks., om laget vises som tiles eller vektor, hvordan klik-info ser ud, og hvilke filtre brugeren får.

## Åbn Meta

1. Vælg laget i lagoversigten under <MenuPath items="Database" />.
2. Klik på <MenuPath items="Meta" /> i værktøjslinjen.
3. Ret felterne, og klik på <MenuPath items="Opdater" />.

<figure class="centered-figure">
  <img src={metaDialogSvg} alt="Meta-dialogen med grupperne CKAN, Konflikt og Info pop-up øverst og knappen Opdater markeret nederst" style={{ width: '470px', maxWidth: '100%' }} />
  <figcaption>Meta-dialogen er en lang formular med en gruppe pr. emne.</figcaption>
</figure>

Vælger du flere lag, er alle grupper lukket. Sæt flueben ved de grupper, du vil ændre. Kun felterne i de grupper gemmes på lagene, og lagenes øvrige indstillinger bevares.

Genindlæs Vidi for at se ændringen.

:::caution[JSON og JavaScript]
Flere felter tager JSON eller JavaScript. GC2 kontrollerer ikke indholdet. Er der en fejl, ignorerer Vidi indstillingen og skriver kun fejlen i browserens konsol (F12). Test derfor hver ændring i Vidi.
:::

:::tip[Skriv koden i en editor]
Felterne i Meta-dialogen er små. Skriv templates og funktioner i en editor som Notepad++ eller Visual Studio Code, og kopier dem ind i feltet bagefter. Gem gerne koden i en fil, så du har en kopi. Du kan også trække Meta-dialogen større i hjørnet.
:::

## Layer type

**Type** bestemmer, hvilke visninger laget kan have i Vidi. **Default** er den visning, laget starter med. Vælger du flere typer, kan brugeren skifte mellem dem ved laget i lagstyringen.

<figure class="centered-figure">
  <img src={metaLayerTypeSvg} alt="Gruppen Layer type i Meta-dialogen, hvor Tile og Vector er valgt under Type, og Default er Vector" style={{ width: '484px', maxWidth: '100%' }} />
  <figcaption>Laget kan vises som Tile og Vector og starter som Vector.</figcaption>
</figure>

| Type | Visning |
|---|---|
| **Tile** | Færdigtegnede kortbilleder fra GC2 med lagets styling fra fanen <MenuPath items="Kort" />. Standard for nye lag. |
| **Vector** | Objekterne hentes ind i browseren og tegnes der. Kræves for at kunne snappe til laget og bruge tabellen ved siden af kortet. Brug det kun til lag af en rimelig størrelse. |
| **MVT** | Vektordata hentet i tiles. Kan bruges til større lag end **Vector**. |
| **WebGL** | Tegnes af grafikkortet. Til mange simple objekter, men med færre funktioner i lagstyringen. |

Vector bruger ikke lagets styling fra fanen <MenuPath items="Kort" />, men sin egen [Style function](#style-function).

Se [Teknisk arkitektur og lagvisning](/gc2/teknisk-arkitektur-og-lagvisning) for, hvordan data går fra databasen til kortet.

Værktøjer, der er åbne, når brugeren tænder laget. Skriv dem som en JSON-liste:

```json

```

Mulige værdier er `filters`, `opacity`, `labels`, `search`, `style`, `load-strategy` og `download`. Værktøjet åbnes kun, hvis det findes for lagets type.

### Pop-up template

Erstatter hele klik-info for laget. Templaten er HTML med lagets felter i dobbelte krøllede parenteser:

```handlebars
<h3>{{naturtype}}</h3>
<p>Areal: {{areal_ha}} ha</p>
<p>Status: {{status}}</p>
```

Hjælpefunktionerne fra feltets [Template](/gc2/skemaindstillinger/database/tabelstruktur-data-og-felter#template) virker også her, f.eks. `{{formatDate dato "DD-MM-YYYY"}}`. Er laget redigerbart, tilføjer Vidi selv knapperne til at rette og slette over templaten.

Uden en Pop-up template bruger Vidi denne, som viser felterne med **Vis i klik-info** og deres alias. Den er et godt udgangspunkt, hvis du vil beholde felterne og tilføje noget:

```handlebars
<div class="vidi-popup-content">
  <h3 class="popup-title">{{_vidi_content.title}}</h3>
  {{#_vidi_content.fields}}
    {{#if value}}
      <h4>{{title}}</h4>
      <p {{#if type}}class="{{type}}"{{/if}}>{{{value}}}</p>
    {{/if}}
  {{/_vidi_content.fields}}
</div>
```

#### Eksempel med faneblade

Vidi indeholder Bootstrap og Bootstrap Icons, så templaten kan bruge deres klasser, f.eks. kort, badges og faneblade. Giv fanebladenes `id` objektets `gid`, så de ikke blandes sammen, når flere objekter er åbne:

```handlebars
<div class="card border-0 shadow-sm">
  <div class="card-header text-white d-flex align-items-center gap-2" style="background: #2E7D32">
    <i class="bi bi-tree-fill"></i>
    <strong>{{naturtype}}</strong>
    <span class="badge bg-light text-success ms-auto">{{status}}</span>
  </div>
  <ul class="nav nav-tabs nav-fill small">
    <li class="nav-item"><button class="nav-link active" data-bs-toggle="tab" data-bs-target="#oversigt-{{gid}}">Oversigt</button></li>
    <li class="nav-item"><button class="nav-link" data-bs-toggle="tab" data-bs-target="#registrering-{{gid}}">Registrering</button></li>
  </ul>
  <div class="tab-content card-body p-2">
    <div class="tab-pane active" id="oversigt-{{gid}}">
      <div class="text-center py-2">
        <div class="fs-4 fw-bold">{{formatDecimalNumber areal_ha}} ha</div>
        <div class="small text-muted">Areal</div>
      </div>
      <a class="btn btn-sm btn-outline-success w-100" href="https://arealinformation.miljoeportal.dk" target="_blank">
        <i class="bi bi-box-arrow-up-right"></i> Danmarks Arealinformation
      </a>
    </div>
    <div class="tab-pane" id="registrering-{{gid}}">
      <dl class="row small mb-0">
        <dt class="col-5">Besigtiget</dt>
        <dd class="col-7">{{#if dato}}{{formatDate dato "DD-MM-YYYY"}}{{else}}<span class="text-danger">Ikke besigtiget</span>{{/if}}</dd>
        <dt class="col-5">Datagrundlag</dt>
        <dd class="col-7">{{kilde}}</dd>
        <dt class="col-5">Myndighed</dt>
        <dd class="col-7">{{myndighed}}</dd>
      </dl>
    </div>
  </div>
</div>
```

Linjen med `{{#if dato}}` viser datoen, hvis feltet har en værdi. Er feltet tomt, vises teksten efter `{{else}}`, her "Ikke besigtiget".

### Function

JavaScript, der køres, når brugeren klikker på et objekt i laget. Denne funktion zoomer kortet ind til objektet:

```js
function (feature, layer, layerKey, sqlQuery, store, map) {
  map.flyToBounds(L.geoJSON(feature).getBounds(), { maxZoom: 14, padding: [80, 80] });
}
```

`feature` er objektet som GeoJSON, og `feature.properties` indeholder dets felter. `map` er Leaflet-kortet. `maxZoom` forhindrer, at kortet zoomer helt ind på små objekter, og `padding` giver plads til klik-info.

### Select function

JavaScript, der køres, når et objekt bliver valgt i klik-info. Det sker, når brugeren klikker på objektet i kortet, og når brugeren vælger en anden række i tabellen under **Info**. Denne funktion filtrerer laget, så det kun viser objekter med samme naturtype som det valgte:

```js
function (id, layer, key, sqlQuery) {
  api.filter(key, {
    match: 'any',
    columns: [{ fieldname: 'naturtype', expression: '=', value: layer.feature.properties.naturtype, restriction: false }]
  });
}
```

`layer.feature.properties` indeholder det valgte objekts felter, og `key` er lagets navn. Filteret sættes med [Vidis JavaScript-API](#filtrer-lag).

## Tile settings

| Felt | Virkning |
|---|---|
| **Use tile cache** | Laget hentes fra tile cachen. Når brugeren filtrerer laget, hentes det uden cache. Se [Tile cache](/gc2/skemaindstillinger/kort/tile-cache). |

## Vector settings

Gælder kun, når laget vises som **Vector**.

| Felt | Virkning |
|---|---|
| **Load strategy** | `Static` henter alle objekter én gang. `Dynamic` henter kun objekterne i kortudsnittet og henter igen, når brugeren flytter kortet. |
| **Max features** | Det største antal objekter, laget må have. Formularen foreslår 500. Står feltet tomt, bruger Vidi 100. Se boksen nedenfor. |
| **Use clustering** | Punkter tæt på hinanden samles i én klynge med et tal. |
| **Show table** | Lagets tabel vises ved siden af kortet. Placering og størrelse sættes med [`vectorTable`](/gc2/konfigurationer/alle-indstillinger#vectortable) i Vidi-konfigurationen. |
| **Reload interval** | Laget hentes igen med dette interval i millisekunder, f.eks. `60000` for hvert minut. **Reload callback** er en funktion, der køres efter hver indlæsning. |
| **Disable feature info** | Klik på laget viser ikke klik-info. |
| **Min zoom** og **Max zoom** | Laget vises kun mellem disse zoomniveauer. |
| **Line highlight style** | En ekstra streg, der altid tegnes under hver linje. Den giver linjen en kant, som en Style function ikke kan lave alene, så linjerne står tydeligere frem på kortet. Skrives som JSON, f.eks. `{"color": "#FFEB3B", "weight": 8}`. |

:::caution[Har laget flere objekter end Max features, vises ingen]
Vidi viser ikke de første objekter op til grænsen, men slet ingen. Brugeren får i stedet beskeden "Det maksimale antal objekter blev nået. Brug filtrer til at reducere antallet." Sæt **Max features** højere end antallet af objekter i laget, eller brug `Dynamic`, så grænsen kun gælder objekterne i kortudsnittet.
:::

### Style function

Uden en style function tegner Vidi laget med en standard blå farve. Funktionen får hvert objekt og returnerer Leaflet-styling. Den kan bruge objektets felter:

```js
function (feature) {
  if (feature.properties.type === 'Kirkefredning') {
    return { color: '#B71C1C', weight: 3, fillOpacity: 0.1 };
  }
  return { color: '#6A1B9A', weight: 2, fillColor: '#AB47BC', fillOpacity: 0.35 };
}
```

`color` og `weight` er kanten, og `fillColor` og `fillOpacity` er fladen.

### Point to layer

Bestemmer, hvordan punkter tegnes. Uden en funktion vises punkterne som Leaflets standardmarkør. Denne funktion tegner dem som grønne cirkler:

```js
function (feature, latlng) {
  return L.circleMarker(latlng, { radius: 6, color: '#1B5E20', weight: 2, fillColor: '#66BB6A', fillOpacity: 0.9 });
}
```

Punkterne kan også vises som et ikon, f.eks. en SVG- eller PNG-fil:

```js
function (feature, latlng) {
  return L.marker(latlng, {
    pane: 'natur-udsigtspunkter',
    icon: L.icon({ iconUrl: 'https://example.dk/ikoner/udsigt.svg', iconSize: [24, 24], iconAnchor: [12, 12] })
  });
}
```

## Filters

Her sættes filtrene op, som brugeren finder under filterværktøjet ved laget. Hvordan brugeren bruger dem, er beskrevet under [Lagstyring](/vidi/vidi-menuen/lagstyring).

### Filter config

Rækker, der er klar på fanen **Vilkårlig**, så brugeren kun skal udfylde værdien. Brugen er beskrevet under [Standardfiltre](/vidi/vidi-menuen/lagstyring#standardfiltre).

```json
[
  {"field": "naturtype", "operator": "="},
  {"field": "besigtiget", "operator": ">="}
]
```

Felterne skal kunne filtreres. Har et felt **Deaktiver filtrering** under [Struktur](/gc2/skemaindstillinger/database/tabelstruktur-data-og-felter#søgning-og-filtrering), vises rækken uden felt.

Har feltet en værdiliste i [Egenskaber](/gc2/skemaindstillinger/database/tabelstruktur-data-og-felter#egenskaber), vælger brugeren værdien i en rulleliste.

### Øvrige felter

| Felt | Virkning |
|---|---|
| **Default match** | Om rækkerne på fanen **Vilkårlig** kombineres med `All` (AND) eller `Any` (OR) fra start. Standard er `Any`. |
| **Immutable** | Brugeren kan kun udfylde rækkerne fra **Filter config**. Brugeren kan ikke tilføje eller fjerne rækker, skifte mellem AND og OR eller bruge **Filter editor**. |
| **Required** | Laget vises først, når brugeren har sat et filter. Godt til store lag, der kun giver mening i udsnit. |

:::caution[Filtre er ikke adgangskontrol]
Et filter skjuler kun data i Vidi. Data, som brugerne ikke må se, skal beskyttes med [authentication og privilegier](/gc2/skemaindstillinger/database/privilegier-og-authentication).
:::

## References

Når brugeren filtrerer laget, filtreres de lag, der står i **Referenced by**, også.

I eksemplet har et lag med fredede områder fået **Referenced by**, der peger på et lag med udsigtspunkter. Hvert udsigtspunkt har fredningens `gid` i feltet `fred_gid`. Filtrerer brugeren de fredede områder, vises kun udsigtspunkterne i de fredninger, der er tilbage:

```json
[
```

| Nøgle | Betydning |
|---|---|
| `rel` | Det andet lag, der også filtreres, skrevet som `skema.tabel`. I eksemplet udsigtspunkterne. |
| `parent_column` | Feltet i dette lag. I eksemplet fredningens `gid`. |
| `child_column` | Feltet i det andet lag, der skal matche `parent_column`. I eksemplet `fred_gid`. |

## Konflikt

:::tip[Kræver conflictSearch]
Felterne virker kun, når udvidelsen `conflictSearch` er slået til i Vidis konfiguration under [`enabledExtensions`](/gc2/konfigurationer/alle-indstillinger#enabledextensions).
:::

[Konfliktsøgningen](/vidi/vidi-menuen/konfliksoegning) søger i alle lag med geometri i Vidi-konfigurationens skemaer, også lag, der ikke er tændt. Baggrundskort og lag med **Skip conflict** under [Lagets grundindstillinger](/gc2/skemaindstillinger/database/lagets-grundindstillinger) springes over. Resultatet viser de felter, der har [Vis i konflikt](/gc2/skemaindstillinger/database/tabelstruktur-data-og-felter#vis-i-konflikt).

Felterne under **Konflikt** styrer, hvad der vises om laget i resultatet:

| Felt | Virkning |
|---|---|
| **Short description** | Tekst under lagets navn på fanen **Data fra konflikter**. |
| **Long description** | Tekst bag linket **Lagbeskrivelse - klik her** på fanen **Data fra konflikter**. Teksten kommer også med i rapporten. |
| **Buffer** | Ekstra buffer i meter for netop dette lag. Den lægges oven i brugerens buffer og vises på fanen **Med konflikter**. |
| **Analyse** | SQL, der opsummerer konflikterne i en tabel på fanen **Analyse**. |
| **Analyse header** | Overskriften på analysetabellens første kolonne. |

Begge beskrivelser kan indeholde HTML.

I eksemplet har laget med beskyttede naturtyper fået en kort og en lang beskrivelse, en buffer på 10 m og en analyse, der opgør konflikterne pr. naturtype. **Analyse header** er `Naturtype`, og **Analyse** er:

```sql
select json_object_agg(natyp_navn, json_build_object('Antal', antal, 'Areal (ha)', areal))
from (
  select natyp_navn, count(*) as antal, round(sum(areal_ha), 1) as areal
  from natur.beskyttede_naturtyper
  where @WHERE@
  group by natyp_navn
) t
```

Vidi erstatter `@WHERE@` med en betingelse, der finder lagets objekter i søgeområdet inklusive bufferen. SQL'en skal returnere ét JSON-objekt. Hver nøgle bliver en række i tabellen, og nøglerne i det indre objekt bliver kolonner. Her giver det én række pr. naturtype med kolonnerne Antal og Areal (ha).

## Vidis JavaScript-API

Vidi har et lille JavaScript-API, som du kan bruge i lagenes templates og funktioner. Med det kan du f.eks. tænde et andet lag eller filtrere et lag, når brugeren klikker på et objekt.

API'et hedder `api` og findes i:

- [Function](#function) og [Select function](#select-function) under Info pop-up
- [Pop-up template](#pop-up-template), f.eks. i en knap med `onclick`

:::note[Indlejrede kort]
`api` virker kun inde i Vidi. Skal en hjemmeside styre et indlejret Vidi-kort, så brug [Embed API](/vidi/extensions/embed#embed-api).
:::

### Funktioner

| Funktion | Virkning |
|---|---|
| `api.turnOn(lag)` | Tænder laget. Er laget allerede tændt, sker der ingenting. |
| `api.turnOff(lag)` | Slukker laget. |
| `api.setView([breddegrad, længdegrad], zoom)` | Flytter kortet til punktet og zoomniveauet. |
| `api.filter(lag, filter)` | Sætter et filter på laget, som brugeren selv kan på fanen **Vilkårlig**. |
| `api.sqlFilter(lag, sql)` | Sætter et filter som SQL, som i **Filter editor**. |
| `api.resetFilters(lag)` | Fjerner filtrene fra `filter` og `sqlFilter`. |

`lag` er lagets navn som `skema.tabel`, f.eks. `natur.fredede_omraader`. `turnOn` kan også tage lagtypen som præfiks, f.eks. `v:natur.fredede_omraader` for at tænde laget som vektor. Præfikset virker kun, hvis typen er valgt under [Layer type](#layer-type).

### Tænd og sluk lag

En knap i en Pop-up template, som tænder et andet lag:

```html
<button class="btn btn-sm btn-outline-success" onclick="api.turnOn('natur.skovbyggelinjer')">
  Vis skovbyggelinjer
</button>
```

### Flyt kortet

```js
api.setView([56.112, 9.556], 14);
```

Koordinaterne er breddegrad og længdegrad i WGS84. Zoomniveauet er det samme som i Vidis URL.

### Filtrer lag

`api.filter` tager et filter med samme opbygning som fanen **Vilkårlig**:

```js
api.filter('natur.beskyttede_naturtyper', {
  match: 'any',
  columns: [
    { fieldname: 'naturtype', expression: '=', value: 'Mose', restriction: false }
  ]
});
```

| Nøgle | Betydning |
|---|---|
| `match` | `any` (OR) eller `all` (AND) mellem rækkerne |
| `columns` | Én række pr. betingelse |
| `fieldname` | Feltets navn i databasen |
| `expression` | `=`, `<>`, `<`, `>`, `<=`, `>=` eller `like`. `like` finder tekst, der indeholder værdien. |
| `value` | Værdien som tekst |
| `restriction` | Skal være `false` |

Har laget [Predefined filters](#predefined-filters), lægges filteret oven i dem med AND.

`api.sqlFilter` erstatter derimod lagets øvrige filtre, ligesom **Filter editor**:

```js
api.sqlFilter('natur.beskyttede_naturtyper', "naturtype = 'Mose' AND areal_ha > 5");
```

`api.resetFilters` fjerner begge slags filtre igen. Lagets Predefined filters bliver.

:::caution[Kendt fejl i resetFilters]
Ligger laget i en gruppe, som brugeren ikke har foldet ud i lagstyringen, giver `api.resetFilters` en fejl, og laget bliver tomt. Fjern i stedet et filter fra `api.filter` med `api.filter(lag, { match: 'any', columns: [] })`. Et filter fra `api.sqlFilter` kan i den situation ikke fjernes via API'et.
:::

## Egne grupper

Den, der driver GC2, kan tilføje egne grupper til Meta med `metaConfig` i GC2's `App.php`. Grupperne vises øverst i dialogen, og værdierne gemmes i lagets meta sammen med de andre felter. Vidi bruger dem ikke selv. De bruges af egne udvidelser til Vidi eller af andre systemer, der læser lagenes meta via GC2's API. De kan også bare bruges til at dokumentere lagene, f.eks. hvem der er dataansvarlig:

```php
"metaConfig" => [
    [
        "fieldsetName" => "Drift",
        "fields" => [
            ["name" => "dataansvarlig", "type" => "text", "title" => "Dataansvarlig"],
            ["name" => "opdatering", "type" => "combo", "title" => "Opdateres",
                "values" => [
                    ["name" => "Dagligt", "value" => "dagligt"],
                    ["name" => "Månedligt", "value" => "maanedligt"],
                    ["name" => "Ved behov", "value" => "ved_behov"],
                ]],
        ],
    ],
],
```

`name` er nøglen i lagets meta, og `title` er feltets navn i dialogen. `type` kan være `text`, `textarea`, `checkbox`, `combo` eller `checkboxgroup`. `combo` og `checkboxgroup` tager en liste af valgmuligheder i `values`.

`App.php` ligger i `app/conf/` i GC2-installationen. `metaConfig` skrives i listen `$param` sammen med de andre indstillinger. Filen er ikke med i GC2's repository, men GC2's Docker-opsætning bygger den ud fra skabelonen [docker/conf/gc2/App.php](https://github.com/mapcentia/geocloud2/blob/master/docker/conf/gc2/App.php). Se også [Serverkonfiguration](/gc2/serverkonfiguration). De indbyggede grupper er defineret i `$metaConfig` i [app/inc/Globals.php](https://github.com/mapcentia/geocloud2/blob/master/app/inc/Globals.php) og kan bruges som eksempel.

:::caution[Brug et nyt gruppenavn]
Har en egen gruppe samme navn som en indbygget gruppe, f.eks. `Filters`, erstatter den den indbyggede gruppe i dialogen.
:::

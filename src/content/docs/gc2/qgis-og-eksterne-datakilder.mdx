## QGIS som supplement til GC2

:::note[Krævet adgang]
Du skal have læse- eller skriveadgang svarende til den valgte forbindelse. Direkte databaseadgang og publicering af QGIS-styling kræver særskilt godkendelse og bør ikke antages ud fra GC2-login alene.
:::

QGIS bruges ofte sammen med GC2 når administratorer eller GIS-medarbejdere skal arbejde mere avanceret med data og styling end det der er praktisk direkte i browseren.

Typiske anvendelser er:

- avanceret redigering
- styling i desktop-GIS
- kontrol af geometri og attributter
- publicering af projektbaseret visning

## Data ud af GC2 og ind i QGIS

GC2 stiller normalt services til rådighed, så lag kan hentes ind i QGIS via WFS eller lignende forbindelser. Det gør det muligt at arbejde med de samme data i desktop og web.

Læs også [Tjenester og API](/gc2/skemaindstillinger/database/tjenester-og-api), hvis du har brug for de generelle service-URL'er, passwords eller SQL-adgang.

Hvis I bruger versionering eller workflow, skal integrationen valideres ekstra nøje på den konkrete installation.

## Typisk arbejdsgang i QGIS

En praktisk arbejdsgang ser ofte sådan ud:

1. find service-URL eller databaseforbindelse i GC2
2. opret forbindelsen i QGIS
3. hent de relevante lag ind
4. kontrollér geometri, attributter og styling
5. gem eller publicér ændringer efter jeres aftalte proces

## QGIS-baseret styling

I nogle setup kan et QGIS-projekt uploades eller bruges som kilde til webvisning. Det kan give høj visuel ensartethed mellem desktop og web, men det kræver også mere disciplin i driften.

Ting der er gode at afklare i teamet:

- om styling ejes af GC2 eller QGIS
- hvem der må publicere ændringer
- hvordan performance testes efter stylingændringer

Hvis I bruger QGIS som stylingkilde, så aftal tydeligt:

- hvor projektfiler ligger
- hvem der må overskrive publiceret styling
- hvordan ændringer testes før de kommer i drift
- hvordan man håndterer konflikter mellem QGIS-styling og styling i GC2

En klassisk arbejdsgang fra den ældre GC2-dokumentation er:

1. hent lag ind i QGIS via WFS eller anden relevant forbindelse
2. opsæt styling og gem projektet
3. upload eller publicér projektet som QGIS-lag hvis jeres installation bruger den model
4. opdatér eventuelt tile cache hvis ændringerne ikke slår igennem med det samme

## Eksterne WMS-kilder

GC2 kan også inddrage lag fra eksterne WMS-tjenester. Det er praktisk når I vil kombinere egne data med tredjepartskilder uden at kopiere datasættet ind i egen database.

## Views som integrationslag

Database views er ofte den mest robuste måde at bygge en integrationsvenlig visning på. De kan bruges til at:

- afgrænse datasæt
- skjule tekniske felter
- samle data fra flere tabeller
- klargøre data til embed eller Vidi

Det er ofte en god idé at bruge views når:

- eksterne brugere ikke skal se hele datamodellen
- QGIS-brugere kun skal arbejde med et fagligt udsnit
- Vidi skal have et enklere og mere kontrolleret lag end grundtabellen

Den ældre dokumentation har en mere detaljeret QGIS-proces med skærmbilleder. Vi genintroducerer kun de dele der stadig matcher den nuværende arbejdsgang.
:::
